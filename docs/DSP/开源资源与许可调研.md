#### ★ 技术方法总结（这是本次调研最有价值的产出）

**电路如何映射为 WDF 树**【核验，`EQP1A.h` 正文 + SMC 论文】

论文自己讲明了关键简化：**因为没有真实的输入/输出阻抗要匹配，作者移除了电路的输入与输出电阻，并相应调整其它元件值**，从而让电路可以**只用串联/并联 adaptor**（纯 SPQR 树）建模，**完全不需要 R-Type adaptor**。论文实测：R-Type 版本慢 75%，最终版（无 R-Type）在 48 kHz 下实时率 **217×**，比参考 Faust 实现快 40–47%。这是本项目最该抄的**方法论**：先去端口电阻，避免散射矩阵。

树的结构（`IdealVoltageSourceT` 在根，全部走 S/P adaptor）：

```
Vin(理想电压源)
 └─ S3 : WDFSeries( S2 , J )
     ├─ S2 : WDFSeries( S1 , pEFGHI )
     │   ├─ S1 : WDFSeries( RBoostHi1 , pCD )
     │   │   ├─ RBoostHi1  = (1 − HiBoost) · 12 kΩ     ← 端口 B：高频提升分压上半
     │   │   └─ pCD : WDFParallel( C , RBoostHi2 )
     │   │       ├─ C  : WDFSeries( SCLc , SRQ )       ← 端口 C：谐振 RLC
     │   │       │   ├─ SCLc : WDFSeries( C1 , L1 )        C1 = √(1/(12e6·(2πf)²))，L1 = 12e6·C1
     │   │       │   └─ SRQ  : WDFSeries( RQ , RQ_offset ) RQ = HiBQ·3.9 kΩ，偏置 390 Ω
     │   │       └─ RBoostHi2 = HiBoost · 12 kΩ        ← 端口 D：高频提升分压下半
     │   └─ pEFGHI : WDFParallel( sEFG , sHI )
     │       ├─ sEFG : WDFSeries( RCutHi1 , pFG )      ← 端口 E/F/G：高频衰减搁架
     │       │   ├─ RCutHi1 = (1 − HiCut) · 1 kΩ
     │       │   └─ pFG : WDFParallel( RCutHi2 , CHiCut )
     │       │       ├─ RCutHi2 = HiCut · 1 kΩ
     │       │       └─ CHiCut  : 5k→270nF, 10k→135nF, 20k→68nF
     │       └─ sHI : WDFSeries( H , I )               ← 端口 H/I/J：低频段
     │           ├─ H : WDFParallel( LoFreqC1 , RCutLo )   端口 H：低频衰减搁架
     │           │   └─ RCutLo = LoCut · 110 kΩ
     │           └─ I : WDFSeries( R2 , R3 )               端口 I：1 kΩ + 10 kΩ
     └─ J : WDFParallel( RBoostLo , LoFreqC2 )           ← 端口 J：低频提升搁架
         └─ RBoostLo = LoBoost · 8.2 kΩ
```

**关键设计模式：电位器 = 两个可变电阻的分压。** 所有增益旋钮都不是"改增益系数"，而是把一个固定上限电阻 `R_MAX` 拆成 `(1−g)·R_MAX` 与 `g·R_MAX` 两个串联电阻，分别接在树的不同分支上。`g ∈ [0, 1]` 归一化，`g = 0.00001` 为初始值（不是 0，避免除零/零阻抗）。这是"忠实还原电位器物理行为"的做法，也是它能自然产生 Pultec 低频魔术的原因。

**元件值常量**【核验，`EQP1A.h`】

| 常量 | 值 | 说明 |
|---|---|---|
| `RBOOSTHI_MAX` | 12 kΩ | 高频提升电位器总阻 |
| `RQ_MAX` | 3.9 kΩ | 高频带宽（Q）电位器总阻 |
| `RQ_OFFSET_VALUE` | 390 Ω | Q 的固定偏置（保证最小 Q 不为零） |
| `RCUTHI_MAX` | 1 kΩ | 高频衰减电位器总阻 |
| `RBOOSTLO_MAX` | 8.2 kΩ | 低频提升电位器总阻 |
| `RCUTLO_MAX` | 110 kΩ | 低频衰减电位器总阻 |
| `RATIO_L1_C1` | 12 × 10⁶ | L1/C1 比值恒定 → 用 √(1/(ratio·ω²)) 反推 C1，L1 = ratio·C1 |
| `R1_VALUE / R2_VALUE / R3_VALUE` | 91 Ω / 1 kΩ / 10 kΩ | 固定电阻网络 |

**低频档位的电容值**（`LoFreqC2`；`LoFreqC1 = LoFreqC2 / 30`）【核验，`EQP1A.cpp`】：

| 频率 | LoFreqC2 | LoFreqC1 |
|---|---|---|
| 20 Hz | 2.2 µF | 73.3 nF |
| 30 Hz | 1.1 µF | 36.7 nF |
| 60 Hz | 560 nF | 18.7 nF |

**输出与增益补偿**【核验】

```cpp
return (-wdft::voltage<double>(J) + wdft::voltage<double>(R3)) * 15.4882;
```
即：取端口 J 的电压取负、叠加 R3 上的电压，再乘固定系数 **15.4882** 补偿无源级约 16 dB 插入损耗（20·log10(15.4882) ≈ 23.8 dB —— 【推断】这个系数是经验标定值，同时包含了分压网络带来的额外衰减，不只是 16 dB）。**注意：这是与采样率无关的常数，因为它是对无源网络传输比的补偿，不是频率相关量。**

**过采样实现**【核验，`PluginProcessor.cpp`】

```cpp
oversampler.clearOversamplingStages();
for (size_t n = 0; n < osFactor; ++n) {
    auto twUp   = 0.10f * (n == 0 ? 0.5f : 1.0f);
    auto twDown = 0.12f * (n == 0 ? 0.5f : 1.0f);
    oversampler.addOversamplingStage(
        juce::dsp::Oversampling<float>::FilterType::filterHalfBandFIREquiripple,
        twUp,   -90.0f + 10.0f * n,     // 上行阻带
        twDown, -75.0f + 10.0f * n);    // 下行阻带
}
if (osFactor == 0) oversampler.addDummyOversamplingStage();
oversampler.reset();
oversampler.initProcessing((size_t) samplesPerBlock);
osSampleRate = oversampler.getOversamplingFactor() * sampleRate;
setLatencySamples(oversampler.getLatencyInSamples());
```
- 倍率选项 `{"x1","x2","x4","x8","x16"}`，`osFactor = log2(倍率)` 即级数（x2 → 1 级，x16 → 4 级）。
- 用 `getCurrentChoiceName()` 字符串 `substr(1)` 再 `stoi` 反推级数——**这是可改进的写法**（【推断】直接查表更稳）。
- 逐级放宽过渡带（0.10/0.12 → 0.10/0.12 每级相同，但首级减半）并逐级加深阻带（−90/−75 dB，每级 +10 dB）。
- 后补偿 `× 15.4882`（见上）。

**已知可改进点（【推断】，基于我读到的源码）**
1. `osFactorChanged` 的检测在 `processBlock` **末尾**才调用 `prepareOversampling`（会重建 FIR 系数、重新分配缓冲区、调用 `initProcessing`）→ **在音频线程里做了重分配**，不是实时安全的写法。正确做法：在 `parameterChanged`（消息线程）里置标志，在 `prepareToPlay` 或非处理期重建。
2. 逐样本 `osBlock.setSample/getSample` 访问（含边界检查与跨通道计算），可以改用通道指针直接读写。
3. `setLatencySamples` 在 `prepareOversampling` 内调用；倍率切换时延迟会变，宿主 PDC 需要正确处理（JUCE 会发 `latencyChanged` 通知，但宿主行为不一）。

**低频魔术（Pultec low-end trick）的成因**【核验，论文 §1.3 + Figure 2】：
> 手册建议不要同时提升和衰减低频，但**同时施加时，提升曲线与衰减曲线落在略微不同的频段上**。效果是：提升低频增加厚度，同时衰减低中频避免"浑浊"。论文以 60 Hz 同时提升+衰减、两个电位器同位置为例给出实测曲线。

#### ★ 实现思路总结（仅作方法参考，不拷贝代码）

【核验，我读了 `The_SSL-Style_EQ.jsfx` 全文】

1. **整体结构**：`@init` 段预先计算频响曲线用的 cos/sin/2倍角查表（`MEM_C/MEM_S/MEM_C2/MEM_S2`）；`update_filters()` 集中计算所有系数；`@sample` 逐样本处理。

2. **滤波器核心：TPT / ZDF 状态变量滤波器（SVF）**，不是直接 I 型 biquad：
```jsfx
lf_g_coeff = tan($pi * lf_freq / srate);
lf_k_coeff = 1 / lf_q;
lf_a1_svf  = 1 / (1 + lf_g_coeff * (lf_g_coeff + lf_k_coeff));
lf_a2_svf  = lf_g_coeff * lf_a1_svf;
// 逐样本：
v3 = in - s2;
v1 = (s1 + g*v3) * a1;      // 带通/积分器输出
v2 = g*v1 + s2;             // 低通输出
s1 = 2*v1 - s1;  s2 = 2*v2 - s2;
```
这是**梯形积分（trapezoidal / TPT）SVF**的经典形式，零延迟反馈、对调制友好、系数用 `tan()` 预弯（无频率弯曲）。**这正是本项目 SSL 侧应该用的结构**——比 JUCE `CurveEq` 的 RBJ biquad 更适合做比例 Q（Q 随增益变化时必须平滑无爆音）。

3. **★ 比例 Q（proportional Q）的具体公式**：
```jsfx
lmf_norm = abs(lmf_gain) / 15.0;          // 增益归一化到 ±15 dB 量程
// G-Series（Pink）：
lmf_q = lmf_q_base * (1.2 + lmf_norm*lmf_norm * 2.8);
// E-Series（Black）：
lmf_q = lmf_q_base * (0.5 + lmf_norm*lmf_norm * 1.5);
```
**HMF 与 LMF 用同一公式。** 形式为 `Q = Q_base · (a + b · (|gain|/15)²)`，即 **Q 随增益的平方增长**，且 **E 与 G 系列用不同系数**（G 系列 Q 起点更高、随增益增长更陡）。`Q_base` 是用户旋钮值（0.5–3.0）。

【推断】这个二次形式与"SSL 增益越大 Q 越窄"的听感一致；用平方而非线性，使小增益区变化平缓、大增益区快速变窄。**但请注意：这是第三方对 SSL 行为的一种近似拟合，不是从 SSL 官方文档抄来的公式。** 官方并未公布比例 Q 的解析式。

4. **★ 搁架 overshoot 的实现方式**：LF/HF 用 **RBJ 搁架公式**，但 **`Q` 被设为 > 0.707**：
```jsfx
// 文件头自述：RBJ Audio EQ Cookbook formulas used for Resonant Shelves
lf_bell ? ( lf_q = 0.71; ) : ( model_g ? ( lf_q = 1.0; ) : ( lf_q = 1.45; ) );
hf_bell ? ( hf_q = 0.71; ) : ( model_g ? ( hf_q = 1.0; ) : ( hf_q = 1.45; ) );
```
- **G-Series 搁架 Q = 1.0；E-Series 搁架 Q = 1.45；bell 模式 Q = 0.71。**
- 再配合 `alpha = sn/(2Q)`（RBJ 的 alpha 表达式），Q > 0.707 使搁架传递函数的分母在转折频率附近产生共轭极点 → **转折点附近出现增益过冲**，这就是 SSL "overshoot" 的数学来源。

【这是本次调研的一个关键发现，见 §3.4 的数学解释。】

5. **★ 搁架的"第一级 + 谐振级"混合实现**（`@sample` 段）：
```jsfx
// LF（shelf 模式取 v2 低通；bell 模式取 v1*k 带通）
spl0 = inL + ((slider12 ? v1L*lf_k_coeff : v2L) * lf_gain_mod);
// LMF/HMF（纯 peaking：取带通 v1*k）
spl0 = inL + (v1L * lmf_k_coeff * lmf_gain_mod);
// HF（shelf 模式取大增益方向的补充项）
spl0 = inL + ((slider42 ? v1L*hf_k_coeff : (inL - v2L - v1L*hf_k_coeff)) * hf_gain_mod);
```
其中 `gain_mod = (10^(gain_dB/20)) − 1`（即线性增益减 1，保证 0 dB 时输出 = 输入）。**这是"并联式 EQ"结构（直通 + 滤波支路），而非串联 biquad**。优点：0 dB 时数学上精确直通、增益调制时不产生系数跳变。

6. **输入饱和 `sat_console_ssl(x, drive)`**（【推断】这是 Airwindows 风格的不对称软削）：
```jsfx
x *= drive;
asym = x + 0.15 * x * x;                 // ★ 二次项 → 偶次谐波 / 不对称
asym > 1.0 ? ( asym = 0.95 + (asym-1.0)*0.1 ) :
asym < -1.0 ? ( asym = -0.95 + (asym+1.0)*0.1 ) :
               ( asym = asym - 0.15*asym*asym*asym );   // ★ 三次项软削
max(-1.5, min(1.5, asym));
```
**不对称性来自 `+0.15·x²` 项**（产生偶次谐波）；软削区用 `x − 0.15x³`。饱和前后各有一个一阶 DC 阻断器（`y = x − x1 + 0.999·y1`），因为不对称波形会产生直流偏置——**这是必须的配套处理，直接对应工作区 HANDOFF 文档里 Pultec Tanh+Bias 的需求。**

7. **其它可借鉴细节**：输入/输出联动（I/O Link）反向补偿；`slew_threshold = 0.8 * (192000/srate)` 的压摆限制以模拟运放；DC 阻断用 `dcb_R = 0.999`；`denorm = pow(10,-30)` 加在反馈路径防非规格化数（**本项目同样需要，JUCE 里也可用 `juce::ScopedNoDenormals`**）。

### 3.2 比例 Q 与 ×3÷3 结构的查证结果

**比例 Q（proportional Q）**
- 【事实】SSL 4000 E/G 系列 EQ 的 Q 随增益增大而变窄，这是 SSL 公认的设计特征，也是"SSL EQ 一推就紧"的来源。
- 【事实】SSL 官方**没有公布**比例 Q 的解析公式。
- 【核验】我在公开检索中**没有找到 SSL 官方或经同行评议的文献给出比例 Q 公式**。唯一读到明确公式的开源实现是上面 `The_SSL-Style_EQ.jsfx`（专有许可）：`Q = Q_base·(a + b·(|gain|/15)²)`。
- 【推断】这类"二次/平方形式的 Q–增益映射"是社区与第三方厂商的常见做法，**属于对听感行为的经验拟合，不是可引用的"行业标准公式"**。

**⚠️ 结论：比例 Q 应该本项目自己标定，不要把任何第三方的具体系数当成"正确值"。** 做法建议：
1. 结构上采用 `Q_effective = f(Q_knob, gain_dB)`，`f` 随 `|gain_dB|` 单调递增。
2. 系数通过**测量真实 SSL 硬件或权威仿真（如 UAD/Plugin Doctor 曲线）反推**，或用听测 A/B 标定。
3. 用本项目的 `tools/` 里的曲线验证脚本（工作区已有静态验收流程）锁定曲线形状不回归。

**×3 ÷3 结构**
- 【未核验/存疑】我在本次调研中**没有找到能支撑"SSL HMF/LMF 是三段级联 peaking、外层 ×3 内层 ÷3"这一说法的公开可靠来源**。检索到的多为论坛转述，无法核查。
- 【推断】较可能的解释有两种：(a) 指增益补偿式的三段级联结构；(b) 指早期 SSL 电路里用运放/电阻网络实现的固定增益缩放。**在拿到 SSL 官方手册或经核实的电路分析之前，我不建议把 ×3÷3 写进规格。** 如果需要，建议按"三段级联固定 Q peaking（增益×3 → 主 EQ → ÷3）"作为**待验证假设**做一次频响建模对比，看它能否自然产生 SSL 的窄带形状。
- **诚实的结论：这一条我无法给出可靠答案。** 你原有规格里的"×3÷3"目前缺乏可引用依据，建议要么降级为可选实验，要么先做测量验证。

**RBJ 公式要点**【核验，W3C 正文】

```
A     = 10^(dBgain/40)              (仅 peaking / shelving 用)
ω0    = 2π·f0/Fs
α     = sin(ω0)/(2Q)                (Q 模式)
      = sin(ω0)·sinh( (ln2/2)·BW·ω0/sin(ω0) )   (BW 模式)
      = (sin(ω0)/2)·√( (A+1/A)(1/S − 1) + 2 )   (S 模式，仅搁架)
```

- **peakingEQ**：`b0 = 1+αA`, `b1 = −2cosω0`, `b2 = 1−αA`, `a0 = 1+α/A`, `a1 = −2cosω0`, `a2 = 1−α/A`。文档注明 "except for peakingEQ in which **A·Q is the classic EE Q**"，即 RBJ 的 peaking Q 定义做了 A 归一化，使得 **+N dB 与 −N dB 用相同 Q 时严格互逆（得到纯平直通）**。**【这一点对本项目的并行双风味设计很关键：它保证 boost/cut 对称性可预测。】**
- **lowShelf**：
  `b0 = A[(A+1) − (A−1)cosω0 + 2√A·α]`, `b1 = 2A[(A−1) − (A+1)cosω0]`, `b2 = A[(A+1) − (A−1)cosω0 − 2√A·α]`
  `a0 = (A+1) + (A−1)cosω0 + 2√A·α`, `a1 = −2[(A−1) + (A+1)cosω0]`, `a2 = (A+1) + (A−1)cosω0 − 2√A·α`
- **highShelf**：对应形式（见文档）。
- **S 参数**：`S = 1` 时搁架斜率"在保持增益单调递增/递减的前提下尽可能陡"。文档给出 `1/Q = √((A + 1/A)(1/S − 1) + 2)`。

#### ★★ RBJ 搁架为什么"不会" overshoot —— 数学原因，以及如何让它 overshoot

这是本次调研对本项目**最直接可操作的一个结论**。

**推导**：极点在 `a0 z² + a1 z + a2 = 0`，考虑转折频率归一化 `cos ω0 → 1` 附近的简化（或直接看分母的模拟原型）：
- RBJ 搁架的**模拟原型**为
  - lowShelf：`H(s) = A·(s² + (√A/Q)s + A) / (A s² + (√A/Q)s + 1)`
  - highShelf：`H(s) = A·(A s² + (√A/Q)s + 1) / (s² + (√A/Q)s + A)`
- 分母是二阶多项式。当 `Q ≤ 1/√2 ≈ 0.7071` 时，分母的两个极点**实部为负且为实数（或临界阻尼）**，极点不会靠近 `jω` 轴 → **幅频响应单调过渡，无过冲**。
- 当 `Q > 1/√2` 时，分母的判别式变负 → 出现**共轭复极点**，`Q` 越大极点越靠近虚轴 → **转折频率附近出现谐振峰，即 overshoot**。同时过冲量随 `Q` 增大。
- RBJ 文档说 `S = 1` 对应最陡的**单调**搁架，而 `S = 1 ⟹ 1/Q = √((A+1/A)·0 + 2) = √2 ⟹ Q = 1/√2 ≈ 0.7071`。**这正好就是无过冲的临界值。** 于是逻辑闭环：`S=1 (最陡单调) ⟺ Q=1/√2 ⟺ 极点落在临界阻尼边界`。
- 反推：**只要把搁架的 `Q` 取到 1/√2 以上，就得到带过冲的搁架**，且 `Q` 是唯一控制过冲量的旋钮。

**这解释了 `The_SSL-Style_EQ.jsfx` 为什么把 shelf Q 设成 1.0（G）与 1.45（E）**：这是在用 RBJ 搁架公式"故意越界"制造 overshoot。**E 系列过冲更强（Q=1.45），G 系列较弱（Q=1.0）。**

**实现要点（本项目可直接落地）**
1. 用标准 RBJ 搁架系数公式（公开知识）。
2. 把 `Q` 提升到 `1/√2` 以上作为"SSL flavor"控制参数，而不是用 `S`。**注意 RBJ 文档里搁架同时支持 Q 与 S 两种写法，二者由上面那条关系式联系；实现时选 Q 形式更直观。**
3. 【推断】过冲量对 `Q` 非常敏感（`Q` 从 0.707 → 1.45 会使峰值显著抬升），建议用**查表 + 平滑插值**而不是每块重算，并在增益/Q 变化时做参数平滑（工作区 HANDOFF 里"无参数平滑（拧钮可能爆音）"就是这个问题）。
4. **不要用 `juce::dsp::IIR::Coefficients::makeLowShelf` / `makeHighShelf` 直接做 SSL 搁架**——【推断，基于 JUCE 文档与源码惯例】JUCE 的 shelf 工厂函数只接受 `Q`/`gainFactor` 且默认行为对应单调搁架，无法直接表达"故意过冲"，而且其系数在 Q 变化时需要重建。用 TPT SVF 并联结构（见 §3.1 第 5 点）更可控。

**采用建议：✅ 直接采用 RBJ 公式自行实现（公开知识）**，并**明确在文档中说明"搁架过冲通过 Q > 1/√2 实现"**。

**采用建议（ADAA）：⚠️ 【参考方法，自行实现】**
- ADAA 的数学非常简洁：一阶 ADAA 的核心是
  ```
  F1(x) = ∫ f(x) dx                      （非线性函数 f 的原函数）
  y[n]  = ( F1(x[n]) − F1(x[n−1]) ) / ( x[n] − x[n−1] )     当 x[n] ≠ x[n−1]
  y[n]  = f( (x[n] + x[n−1]) / 2 )                          当 x[n] ≈ x[n−1]  （或直接 f(x[n])）
  ```
  **【推断】对 `tanh`：`F1 = ln(cosh(x))`；对 `x − x³/3` 类软削：`F1` 是初等多项式；对不对称 waveshaper（含 `+0.15x²` 项），`F1` 仍可用初等积分求出。** 因此本项目完全可以在**几十行内自行实现**，不依赖任何受限代码。**这比引入 GPLv3 依赖更干净。**
- 一阶 vs 二阶：【推断】一阶 ADAA 实现简单、对高频抑制约 10–20 dB；二阶（用 `F2` 二次原函数）抑制更强但需要额外的状态判断与除法，且在 `x[n] ≈ x[n−1]` 处的数值稳定性更差。**本项目规模下，一阶 ADAA + 2x 过采样 是性价比最高的组合**（论文原话也支持"配合低阶过采样"）。
- ⚠️ **注意**：ADAA 只适用于**静态（无记忆）非线性**。如果非线性在反馈环路内（例如 WDF 里的二极管、或者 Pultec 增益级的管级局部反馈），需要论文里"extended to feedback system"的那种处理，复杂度显著上升。**本项目当前架构里 Pultec/SSL 的染色是串联的静态 waveshaper，所以可以直接用。**

### 4.2 tanh / atan / 不对称 waveshaper 的常见实现与抗混叠

**tanh 与 atan 系**
| 函数 | 特性 | 谐波 |
|---|---|---|
| `tanh(x)` | 对称软削，奇函数 | 纯奇次谐波 |
| `(2/π)·atan(πx/2)` | 与 tanh 形状接近，峰值斜率不同；计算成本低 | 纯奇次 |
| `x / (1 + |x|)` | 极廉价的有理近似，曲线更"软" | 纯奇次 |
| `x − x³/3`（限幅内） | 多项式软削，**有解析原函数 → 最适合 ADAA** | 纯奇次 |

【推断，数学事实】**任何奇函数 waveshaper 只产生奇次谐波**；要出偶次谐波必须有**偶函数分量**（即不对称）。

**不对称 waveshaper 的常见做法**
1. **DC 偏置法（最简单）**：`y = f(x + b) − f(b)`，`b ≠ 0` 引入偶函数分量。**必须配套 DC 阻断器**（否则输出有直流，影响后续处理且被 DAW 测量到）。工作区 HANDOFF 里 Pultec 用的 "Tanh+Bias" 就是这个。
2. **显式二次项（Airwindows/DocShadrach 风格）**：`y = x + a·x²`（然后软削），`a = 0.15` 是常见取值。【核验，`The_SSL-Style_EQ.jsfx` 里正是 `0.15 * x * x`】这类做法产生较强的 2 次谐波。**优点：解析原函数简单，天然适合 ADAA。**
3. **分段/分段多项式**：不同正负半周用不同的曲线（例如正半周用较硬的 `tanh`，负半周用较软的 `x/(1+|x|)`）。**这会产生最多的偶次谐波，也是"电子管味"的主要来源。** ★ 推荐配合 Werner & Azelborn 的 DAFx-23 论文（任意分段多项式的 ADAA）。
4. **Chebyshev 多项式法**：用 `T_n(x)` 的线性组合**直接指定各次谐波的幅度**。`y = Σ c_n T_n(x)`。**优点：谐波含量精确可控、可可视化设计。缺点：`T_n(x)` 在 `|x| > 1` 时爆炸，必须严格限幅在前级，且谐波数受采样率限制（`T_n` 会产生到 n 次谐波，超过 Nyquist 的照样混叠）。** 【推断】适合做"谐波含量 UI"（比如一个"偶次/奇次"混合旋钮），但不适合做随输入电平变化的真实器件行为。

**宽松许可的参考实现**
| 来源 | 许可 | 内容 |

| JUCE `juce::dsp::FastMathApproximations` | AGPLv3/商业【核验】 | `tanh`、`sin`、`cos` 等快速近似，用于避免 `std::tanh` 的高成本。**注意：JUCE 的 tanh 近似在饱和区精度有限，做高保真失真时建议用 `std::tanh` 或自行做有理近似** |

**Koren 模型要点**【推断，基于我对该模型的既有认识，**未在本次调研中一手核验原文**】
- Koren 模型用一组闭式方程描述三极管/五极管的 `Ip(Vg, Vp)` 特性，核心参数为 `μ`（放大系数）、`Ex`（屏流指数）、`Kg1`、`Kp`、`Kvb`。
- 它比原始的 Child-Langmuir（`3/2` 次方定律）更贴合实际电子管特性，是 SPICE 里最常见的电子管模型之一。
- **对本项目的意义**：Pultec 的 12AX7/12AU7 增益级（用于补偿 16 dB 插入损耗）以及 SSL 的输入/输出级。EGP-WDF-1A 论文在 §4.1 Future Work 里明确说这个增益级**没有做**，并给出两条路径：

**★ 论文给出的增益级建模路线（这是本项目独有的价值情报）**【核验，论文 §4.1】
> "Various methods can be used to model the distortion produced by the 12AX7 and 12AU7 vacuum tubes in the EQP-1A's gain stage.
> One option would be to use a **filtering block and a static waveshaper** as proposed in [28, 29]. This is simple to implement but **won't fully model the non-symmetrical distortion present in circuits with pairs of triodes like this one**.
> A more accurate option would involve **integrating vacuum tube models into a WDF implementation**, as discussed in [30, 31]. This would offer high accuracy but might prove challenging due to the **complex interaction between the gain and equalizer stages**.
> Instead of the WDF models of the vacuum tubes, **neural networks** can be introduced into the WDF domain model..."

- 路线 A（滤波器 + 静态 waveshaper）：**实现简单但无法完全表达双三极管的不对称失真**——正是本项目 HANDOFF 里"对称软削，管/运放不等价"的痛点。
- 路线 B（WDF 内嵌电子管模型）：精度高，但"增益级与 EQ 级的复杂交互"很难处理（因为 WDF 只允许树根一个非线性元件）。
- 路线 C（WDF + 神经网络）：论文提及，复杂度最高。
- 论文引用的关键文献（用于进一步查找）：
  - [30] J. Pakarinen and M. Karjalainen, "Enhanced wave digital triode model for real-time tube amplifier emulation"【核验，参考文献列表第 724 行】
  - [28, 29] 滤波器 + 静态 waveshaper 方法

**采用建议：⚠️ 【优先级最低，且明确不建议现在做】**
- 本项目当前架构（Pultec 风味 / SSL 风味 / 并行混合）是**EQ 风味**产品，不是电子管放大器模拟器。
- 用"不对称 waveshaper（§4.2 方法 2/3）+ ADAA + 2x OS"就已经能给出**可听辨的偶次谐波染色**，且成本极低。
- 真正做 Koren + WDF 电子管级会带来：巨大的算力开销、与 EQ 级的耦合稳定性问题、以及需要大量实测标定。
- **建议：除非用户明确要求"高保真电子管级模拟"，否则不做。** 若要做，先做**测量验证**（用真实/仿真数据确认 Koren 模型确实带来可听辨的改进），避免为一个听不出差别的问题投入大量工程。

**API 与语义**【核验，JUCE 9 master 的 `juce_Oversampling.h` 正文】

```cpp
enum FilterType { filterHalfBandFIREquiripple = 0, filterHalfBandPolyphaseIIR, numFilterTypes };

// 便捷构造
Oversampling(size_t numChannels, size_t factor, FilterType type,
             bool isMaxQuality = true, bool useIntegerLatency = false);

// 自定义级联（与默认构造 + clearOversamplingStages 配合）
void addOversamplingStage(FilterType,
                          float normalisedTransitionWidthUp,   float stopbandAmplitudedBUp,
                          float normalisedTransitionWidthDown, float stopbandAmplitudedBDown);
void addDummyOversamplingStage();     // 空操作级，用于统一 "可调倍率" 的代码路径
void clearOversamplingStages();

void   initProcessing(size_t maximumNumberOfSamplesBeforeOversampling);
void   reset() noexcept;
AudioBlock<SampleType> processSamplesUp  (const AudioBlock<const SampleType>& inputBlock) noexcept;
void                   processSamplesDown(AudioBlock<SampleType>& outputBlock) noexcept;

size_t     getOversamplingFactor() const noexcept;
SampleType getLatencyInSamples()   const noexcept;
void       setUsingIntegerLatency(bool) noexcept;
```

**★ 注意点与常见坑**（严格区分文档明说 vs 工程推断）

| # | 内容 | 性质 |
|---|---|---|
| 1 | "This class can be configured to do a factor of **2, 4, 8 or 16** times oversampling, using multiple stages, with polyphase allpass IIR filters or FIR filters, and latency compensation." 即每个 stage 是 2×，级数决定总倍率（2^级数）| **文档明说**【核验】 |
| 2 | `initProcessing` 的文档原文："**Must be called before any processing**, to set the buffer sizes of the internal buffers of the oversampling processing." 参数是**过采样之前**的最大块大小（不是过采样后的）| **文档明说**【核验】 |
| 3 | `processSamplesUp` 文档："Must be called to perform the upsampling, **prior to any oversampled processing**. Returns an AudioBlock referencing the oversampled input signal… **Don't forget to set the sample rate of that processing to N times the original sample rate.**" | **文档明说**【核验】 |
| 4 | `processSamplesDown` 文档："The output signal is **probably delayed by the internal latency** of the whole oversampling behaviour, so don't forget to take this into account." | **文档明说**【核验】 |
| 5 | `getLatencyInSamples` 文档原文："**If you have not opted to use an integer latency then the latency may not be integer**, so you might need to round its value **or to compensate it properly** in your processing code since **plug-ins can only report integer latency values in samples to the DAW**." → **这是最容易被忽略的坑**：不设 `useIntegerLatency=true` 时，线性相位 FIR 过采样的延迟通常**不是整数**，直接 `setLatencySamples((int)getLatencyInSamples())` 会产生**分数样本的相位误差**（与干声混合时尤其明显）| **文档明说**【核验】 |
| 6 | 构造函数参数 `useIntegerLatency` 文档："if true this processor will add some **fractional delay at the end of the signal path** to ensure that the overall latency of the oversampling is an integer." 内部用 `DelayLine<SampleType, DelayLineInterpolationTypes::Thiran> delay { 8 }` 实现 | **文档明说 + 源码**【核验】 |
| 7 | `addOversamplingStage` 文档提示："Upsampling and downsampling filtering have **different purposes**, the former removes upsampling artefacts while the latter removes useless frequency content created by the oversampled process, so usually **the attenuation is increased when upsampling compared to downsampling**." → **上行要比下行更狠**（EQP-WDF-1A 就是 −90 dB 上行 / −75 dB 下行）| **文档明说**【核验】 |
| 8 | "**Note: This creates a 'dummy' oversampling stage, which needs to be removed before adding proper oversampling stages.**"（默认构造函数的注释）→ 用默认构造后必须 `clearOversamplingStages()`，否则会多一级 | **文档明说**【核验】 |
| 9 | FIR（`filterHalfBandFIREquiripple`）= **线性相位、延迟最大**；IIR（`filterHalfBandPolyphaseIIR`）= **延迟最小但 Nyquist 附近有相位失真** | **文档明说**【核验】 |
| 10 | **`isMaxQuality` 参数**只影响便捷构造路径（更高效的滤波器设计 ↔ 更高 CPU）| **文档明说**【核验】 |
| 11 | **切换倍率必须彻底重建**：`clearOversamplingStages()` → 重新 `addOversamplingStage` → `reset()` → `initProcessing(blockSize)`。**这些操作会分配内存/重算 FIR 系数，绝不能放在音频线程**（EQP-WDF-1A 就在 `processBlock` 末尾做了，是可改进点，见 §2.1）| **工程推断**（基于 API 语义与内存分配常识） |
| 12 | 必须在 `prepareToPlay` 里按当前 `maximumBlockSize` 调 `initProcessing`；宿主改变块大小时 JUCE 会重调 `prepareToPlay` | **工程推断** |
| 13 | 参数变化（EQ 增益/Q/频率）若发生在过采样后的处理里，**平滑处理应在过采样域内进行**，否则每 2^n 个样本一次的参数跳变会被上行滤波"抹开"，产生意外的调制失真 | **工程推断** |
| 14 | 非整数延迟 + 干/湿混合（**本项目的 PARALLEL 混合就是干湿混合！**）= 梳状滤波风险。**必须**开 `useIntegerLatency` 或对非过采样支路做等量延迟补偿 | **工程推断，但本项目必须处理** |
| 15 | 若过采样的输入块小于 `initProcessing` 声明的大小，JUCE 内部缓冲足够；但**输出块**必须与输入块同样大小（`processSamplesDown` 按输入块大小写回）| **工程推断** |

**采用建议：✅ 直接依赖（你已经在用 JUCE）。但本项目必须做两件事：**
1. **开启 `useIntegerLatency`，并让 PARALLEL 混合的两条支路延迟严格对齐。** 这是当前架构（并行混合 + 过采样）的**真实风险点**：HANDOFF §7.3 提到"过采样：ShapeFX 4×，滤波/EQ 段不过采样"——如果两条支路一条过采样一条不过，延迟不匹配会导致相位问题而非单纯的"少一点染色"。
2. **倍率切换移到消息线程**（用 `juce::AsyncUpdater` 或原子标志 + 在非处理期重建），不要像 EQP-WDF-1A 那样在音频线程重建。

### 7.4 🚩 立项前必须先解决的两个风险（超出"库选型"范围，但更致命）

**风险 1：HISE vs 纯 JUCE + CMake 的路线未定**
- 当前工程是 **HISE 4.1.0 纯 FX 工程**（`编码\AnalogBlend`，UI 靠 `Interface.js` + filmstrip + `XmlPresetBackups`），DSP 靠 HISE 内置的 CurveEq / ShapeFX。
- 本报告调研的所有 C++ 库（chowdsp_wdf、BSD 数学模块、ADAA、TPT SVF）**都要求你在 C++ 侧写 DSP**。
- 在 HISE 里接入 C++ 有两条路：(a) **SNEX**（HISE 的 JIT 编译 C++ 子集，语法受限、无 STL/模板）；(b) **自定义 HISE 模块**（需要改 HISE 源码并重新编译 HISE）。
- **`chowdsp_wdf` 大量使用 C++14 模板与 `decltype`——SNEX 极可能不支持。** 这条路基本不可行。
- → **【结论】要在本项目用上 WDF，必须偏离 HISE 的 ScriptNode 体系，走"自定义 HISE C++ 模块"或"放弃 HISE 转纯 JUCE"。这个决策必须现在做，它决定了本报告一半内容的可用性。**
- ⚠️ 另需核验 **HISE 自身许可**（【推断】GPLv3 + 商业双授权，未核验）——若 HISE 是 GPLv3，走 AGPLv3 发布没问题；但只要 HISE 是 GPLv3 而你想闭源，就必须买 HISE 商业授权。

**风险 2：并行混合 × 过采样的延迟对齐**
- 当前架构是 6ch 并行（Pultec / SSL / Bleed），Pultec 与 SSL 支路走 `SimpleGain` 后相加。
- 一旦引入过采样（WDF 必需），**两条支路的延迟必须严格相等**，否则 PARALLEL 旋钮一拧就出现梳状滤波/相位抵消，用户会听成"混合时低频变薄"。
- 而且 `juce::dsp::Oversampling` 的**非整数延迟**（文档明说）会让这个问题更隐蔽。
- → **【结论】必须开启 `useIntegerLatency=true`，并给"不过采样的支路"插入等量延迟。这是架构级要求，不是优化项。**
